# UC-042: verification of the nine September 2026 demonstration scenarios

**The nine are not nine months.** They are nine immutable deterministic packs of one reporting period, `PER-2026-09`. Each is built from the clean baseline dataset by a recorded mutation (`uc042_dataset/<scenario>/mutations.json`). The UI says this in the Monthly reports row ("9 demonstration scenarios") and in the month report ("9 demonstration scenarios of this one month … not separate months").

**Method:**
- For each scenario, the engine's pack, served by the P10 backend from `uc042_p10b`, was compared programmatically with the scenario's `answer_key.json`.
- The comparison covered exception IDs and count, the number of non-passing results, severity, evidence status, affected-result count and root cause per exception, as recorded in `p10/ui_audit/evidence/scenario_verification.txt`.
- AI, review and final-pack facts come from the API (`september_scenarios.json`), recorded before any test.
- Every scenario was opened in the browser (inventory steps E20–E42).

**Result:** all nine match their answer keys exactly. No dataset, pack or investigation was modified, and the financial-output hashes before and after the work are identical (`financial_before.json` = `financial_after.json`).

## Should all nine appear in the normal Monthly reports experience?

All nine are needed for the assessment: each demonstrates a distinct engine behaviour. Keeping them as packs of September is accurate, because they share one month's data. What they need is to be clearly labelled as demonstration scenarios, and the UI now does that consistently:
- the row label "9 demonstration scenarios";
- the month notice;
- "Scenario SXX · name" on every pack row, in breadcrumbs and in the workspace eyebrow.

Moving them into a separate "Demonstration scenarios" area is recommended for a production build (R24). It is an owner decision because it changes the period model.
