# Phase 0: Implementation Map (isolated copy `p10/uc042_token_optimisation`)

Inspected 16 Nov 2026 before any change. Line references are to the copy at creation; it is byte-identical to Clone E (manifest `source_manifest_clone_e.json`, tree SHA-256 `62b5b3fd…`).

| Area | Relevant files / functions | Existing behaviour | Planned change (phase) |
|---|---|---|---|
| **Investigation output budget** | `config.provider_settings()` (`UC042_LLM_MAX_TOKENS`, default 8000); `llm.OpenAIInvestigator.__init__` sets `self.max_tokens`; used by `investigate()` (fixed mode), `tool_turn()` (tools mode) **and** `structured_request()` (closing summary) | One shared output budget for investigations and summaries. Truncation is detected in `_check_body` (`status: incomplete`, reason `max_output_tokens` → `LLMCallError(kind="max_output_tokens")`), not retried, and recorded as FAILED / `NOT_VALIDATED` in `_not_published` | **P1A:** separate `UC042_INVESTIGATION_MAX_OUTPUT_TOKENS` (default 12000) for `investigate()` and `tool_turn()` only; the summary keeps `UC042_LLM_MAX_TOKENS`. Concise-output guidance in the prompt. Prompt version bump |
| **Candidate citation handling** | `packet._citation_ids` puts `CAND-*` into `allowed_citation_ids`; `validation.validate_output` refuses a confirmed finding citing a candidate, and contradictions using one; `models.Hypothesis.supporting_evidence` may cite them | The model is offered `CAND-*` as a citable ID with no class distinction, so it puts them in a confirmed finding's `evidence_ids` and the whole investigation is refused (SC5A, 3 of 3) | **P1B:** an explicit `citation_classes` view for the model: `confirmed_finding_ids` (no `CAND-*`) and `hypotheses_only_ids` (`CAND-*`), plus a prompt rule. Stored `allowed_citation_ids` and the validator are unchanged (still refuses) |
| **Closing summaries** | `uc042lib/final_pack/summary.py` (`closing_summary_input`, `_refs`, `validate_closing_summary`, `SUMMARY_INSTRUCTIONS`, `generate_closing_summary`); `final_pack/model.py` (`SummaryItem.source_refs` `min_length=1`) | Clean pack: `allowed_refs` is empty, but every item needs at least one reference, so it is structurally refused. Causal phrases are refused by the validator but not named in the prompt. **`uc042lib/final_pack` is guard-protected** (`tests/test_demo_history.py` PROTECTED digest) | **P2:** prepared as a separate proposed patch and verified in a scratch copy. **Not applied** to this copy: a guard re-pin needs owner approval |
| **API telemetry** | `tool_loop.llm_step` adds usage into an aggregate and appends `provider_response` (IDs only); `llm._meta`; `graph._tools_investigation` and fixed-mode `ai_investigation`; `persistence.investigation_id_from_findings` excludes `usage` and `provider_response` from identity | Per-request usage, latency, incomplete details and input sizes are lost. A fixed-mode failure loses its usage entirely. The summary request ID is stored in summary metadata, but not its per-request usage | **P3:** per-request entries in `provider_response.responses[i]` (turn, IDs, model, status, incomplete reason, usage, latency, input item count and characters); the aggregate equals the sum; usage kept on failure; identity unaffected |
| **Evidence packet rendering** | `prompts.user_message` / `tools_user_message` embed `json.dumps(schema)` and `json.dumps(packet)`; `packet.build_packet`; `packet_sha256` over the canonical packet | Full packet JSON plus a duplicate output schema in every request | **P4:** new `packet_view.py`: a lossless, deterministic, versioned model-facing view. The stored packet is unchanged. `model_view_version` and `model_view_sha256` go in `ModelMetadata`. The duplicated schema is removed (`text_format` unchanged) |
| **Relationship retrieval** | `packet.Collector.add` edges (plan wording), `tools.RELATIONSHIPS` (tool vocabulary), `tools.follow_relationship` | The packet's edges use different labels from the tools, so the model re-follows links already present | **P5:** a "verified links" section computed with exactly the `tools.RELATIONSHIPS` rules over packet records; contextual (date-based) edges and candidates listed separately; prompt rule; optional `ALREADY_ESTABLISHED` short-circuit |
| **Deterministic retrieval** | `packet.retrieve`, `plan_*`, `apply_plan_for`, `routing.route_for` (`generic` / `insufficient_evidence` have no plan); `retrieval.EvidenceStore`; tool functions; `graph.run_investigation(mode=…)`; app `services/investigations._execute` hard-codes `mode="tools"`; fixed mode has **no pre-request size guard** | Model-directed tool rounds supply the extra evidence | **P6:** `det_retrieval.py` builds an extended packet with Python (depth policy, de-duplicated searches, explicit pruning register, `retrieval_rule_version`), plus a fixed-mode size guard. Offline parity harness. **Not** the app default |
